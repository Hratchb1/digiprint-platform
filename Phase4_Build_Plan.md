1. **Tailwind gate confirmed: real frontend was on v3.** Ran Tailwind v3.4.19 (`@tailwind` directives, v3 postcss config), but `package.json` also carried an unused `@tailwindcss/postcss@^4.2.0` — mixed state, now cleaned up. `tailwind-merge` was missing. v3→v4 upgrade done as Step 1 (see progress log).

PRD steps 8/9/11 are restyles/rewires, not greenfield. Existing logic (twin checks, blank marking, drive links) must be preserved.
3. **Frontend status vocab is stale.** OrdersPage filters on `booked/scanned/blank/print_ready/archived`; OrderDetailPage transition map uses `processing`. Note: `border_scan_status === 'processing'` in OrderDetailPage is border-scan state, NOT order status — do not rename.
4. **`lib/api.ts` has no Phase 3 endpoints** — no discard, no refund-warnings, only old `/dashboard/stats`.

## Decisions locked

- Keep real JWT auth; drop the prototype's operator login modal (repurpose as operator-ID field only if needed).
- Dashboard uses `needs_attention` **count only** — never render the 2,922 UUID array.
- Intake UX fix: inbound order + 0 rolls → skip "already exists" modal, straight to intake flow.
- Rolls table keeps old status vocabulary (migration 003 was orders-only).
